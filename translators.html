02 / Languages & translators
Choose the right level.
High-level code is usually easier to write, read and maintain. Low-level code offers close control of hardware, but is harder to write and less portable.
Does low-level always mean faster?
No. It can allow careful control of speed and memory use, but results depend on the code and tools. Compilers can optimise high-level programs very effectively.
03 / Languages & translators
Why is translation needed?
A CPU executes its machine instructions. High-level source code needs a translator. Assembly also needs translation; machine code for the correct processor can execute directly.
Build the compiled route
Choose the next stage, starting with what the programmer writes.
    The compiled route here includes producing a runnable program. Real toolchains may also need linking and libraries; you do not need those details today.
    Can it run on another computer?
    High-level source can often be reused with suitable tools and any necessary changes. A compiled program needs a compatible processor and operating system.

    About the syntax-error demonstration
    Our classroom interpreter processes one instruction at a time, so it can print “Starting” before reaching the malformed instruction. Real Python checks a whole script’s syntax before executing it; a syntax error can prevent any of that script from running.
    06 / Languages & translators
    Explain your recommendation.
    Choose a suitable approach, then read the reason. Focus on the needs of the situation rather than memorising that one approach is always better.
    A note about sharing compiled programs
    A compiled program can be supplied without its original source code. This does not make it impossible to inspect or reverse engineer. It may still need libraries or other runtime support, even though the compiler itself is not needed to run it.

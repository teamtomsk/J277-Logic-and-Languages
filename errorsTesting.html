Running is not the same as working.

Testing compares what a program actually does with what it should do. Work out the expected result before running a test.

02 / Errors & testing

What kind of mistake?

A syntax error breaks the rules of the language. A logic error makes the algorithm behave incorrectly. Use the clues, then choose a repair.

What about an error while running?
Some problems, such as division by zero or an undefined name in Python, appear when a statement executes. They are run-time errors, not automatically syntax errors. Today’s main focus is syntax and logic.
03 / Errors & testing
When should we test?
Iterative testing checks parts while a program is being developed. Final (terminal) testing checks the completed program at the end of development.
Develop → test → fix → test again. After a change, repeat earlier tests too: the fix might affect something else. Passing selected tests does not prove that every possible error is gone.
04 / Errors & testing
Choose data that tells you something.
Our booking form needs an integer from 1 to 6 inclusive. Check ordinary values, both accepted edges, values outside the range and wrong data types.
Normal: an ordinary accepted value, such as 3.
Boundary: the accepted edge, 1 or 6.
Invalid: right type, unacceptable value, such as 0 or 7.
Erroneous: wrong type, such as “three” or 2.5 when an integer is required.
Boundary values are valid too. When choosing one category here, use the more specific label “Boundary” for 1 and 6. Values just outside those limits are classified as invalid in this lesson, following OCR’s definitions.
05 / Errors & testing
Build a test plan.
Before you run a test, choose its input, purpose and expected result. Then compare the actual result. Rejecting bad input correctly is a PASS.
Booking rule: integer 1–6 inclusive
The first version contains a mistake: it accepts quantities greater than 1 and less than 6. Your tests should expose it.
Suggested test set
Use 3 (Normal, Accept), 1 and 6 (Boundary, Accept), 0 and 7 (Invalid, Reject), and three (Erroneous, Reject). Choose the refined version to rerun the same tests. This small set covers the key cases, not every possible input.
